# VELORA product assistant

## Implementation

The mobile chatbot uses Firebase AI Logic with the Gemini Developer API; it does
not depend on a worker running on the developer's Mac. The default model is
`gemini-3.5-flash-lite`. No Gemini API secret or service-account JSON belongs in
the app. Firebase manages provider authentication.

Edit `assets/ai/velora_assistant.md` to change the assistant's role and rules.
The file is bundled in the app, so rebuild after changing it. It is an instruction
file, not model training or a full catalog index.

Each advice request retrieves up to 40 current Firestore products, narrowing by
category when recognized. The assistant receives public titles, descriptions,
brands, prices and in-stock variation combinations. This is a bounded subset of
the catalog, not exhaustive search. Three prior conversation turns are retained
in memory; opening a private account action clears them. Replies use Markdown.
Product cards are accepted only for IDs in the current in-stock context. This
validation does not guarantee that every sentence generated by a model is correct.

Order, return, cart, voucher and payment queries stay in the existing local app
service. Their account results and conversation history are not sent to Gemini.
Email addresses and Vietnamese phone numbers are blocked before generation;
other personal data in user-entered text cannot be reliably detected. The welcome
message asks customers to leave out personal and payment details. Remote Markdown
images and external link actions are disabled.

## Console setup

On 2026-11-25 the owner authorized the Gemini terms and API enablement.
Firebase AI Logic setup completed with Gemini Developer API on Spark; optional
AI monitoring was left disabled. Both Gemini API and Firebase AI Logic API show
API Enabled. Free usage has quotas and is not unlimited. Do not link billing
for this setup. A live app request is still awaiting App Check debug registration.

AI Logic requires valid App Check tokens. Debug mobile builds select the debug
provider: register each test installation's debug token in Firebase App Check;
keep those tokens out of source control and chat. Release iOS selects App Attest:
the iOS app is already registered in App Check for Team 838H98FR7Y.
`RunnerProfile.entitlements` includes the production App Attest environment.
The Apple App Attest capability/provisioning must also be available before
release testing. Android release uses Play Integrity and
requires registration with the correct package and signing certificate. Web AI
is intentionally disabled until its own App Check provider is configured.

After provider setup, fully restart/rebuild the app (a hot reload cannot install
a new native plugin), then ask for an in-stock shoe within a budget, follow up
with a color/size question and verify the product details. Test a private order
question separately. Provider errors show a retry/support message; quota errors
show a request-limit message.

## Verification

`flutter test --no-pub test/velora_gemini_assistant_test.dart`

Tests inject a fake provider to verify grounding, variation stock, currency,
invalid responses, private routing and bounded history. They do not prove that
Firebase API activation, App Check or a real device request succeeds.
